# 日志与诊断

日志统一写入 `<PackageRoot>/data/diagnostics/logs`。宿主完成存储初始化后创建进程共用日志器，启动、插件、原生界面、WebView 和退出阶段复用同一实例。存储标记提交前不创建日志目录。

## 记录与容量

- 使用 NLog 6.2.0 写入 UTF-8 JSONL，文件名为 `nori_日期_运行实例.jsonl`，大小轮转后追加卷号。
- 默认记录 Info 及以上。诊断页可以临时调整为 Trace、Debug、Info、Warn、Error 或 Fatal；重启恢复 Info。
- 业务线程只做安全处理、更新最近 500 条内存记录及入队，文件写入和维护在独立后台任务执行。磁盘队列最多 2,048 条，满时拒绝新磁盘记录并增加丢弃计数，内存记录仍可查询。
- 单卷轮转阈值为 8 MiB，总容量为 64 MiB，保留七天。轮转阈值最多超出一条有界记录，容量清理在后台批次结束执行。仅处理已知命名的普通文件，不跟随链接；当前活动卷不删除。
- 旧的 `backend_日期.log`、`frontend_日期.log` 不转换，按七天策略过期，不参与新格式总容量清理。其他文件不自动删除。
- 每条消息最多 1,000 字符；标识字段限制字符集和长度，完整 JSON 记录不超过 8 KiB。UTC 时间保留毫秒以上精度，递增序号决定同一运行实例内的显示和写入顺序。

## 隐私和接入

`FileLogger.Write` 接受固定事件描述、来源、级别、模块和事件编号，可选异常、窗口标识及随机操作关联 ID。未显式提供模块和事件编号时使用调用代码文件名与成员名，不记录调用文件路径。异常只提取类型和自有代码位置，不序列化异常消息、堆栈正文或任意对象。

调用者不得传入聊天、提示词、记忆、语音、请求正文、工具参数/结果、用户身份和凭据。中央脱敏是最后一道防线，不能代替调用点的数据白名单。插件自定义日志正文及 Cubism 原始输出统一转为固定诊断事件。

前端通过 `services/runtime/logging.ts` 发送稳定事件。`write_log` 保留旧参数兼容，但宿主不记录客户端自由消息、模块或来源字段；消息由事件白名单生成，窗口身份由真实桥接来源决定。原生设置测试日志归属 backend。全局错误及反馈层每分钟最多转发五次同类错误，另发一次限流事件；转发失败不递归。

`get_recent_logs` 保留 `time/level/source/message` 字段并增加结构字段。`get_logging_status` 返回当前级别、累计丢弃/写盘失败次数和安全错误类型；`set_logging_level` 仅调整当前运行。这些管理命令只向主窗口及原生设置授权，插件不能调整宿主级别。

本地日志与 Sentry 授权相互独立，不自动上传本地文件。诊断 ZIP 仍只包含最近 200 条安全记录和白名单运行信息，最大 8 MiB，不扫描历史文件。

## 生命周期与界面

写盘故障最多保留一个待重试条目，其余记录留在有界队列中，每秒重试。恢复成功后清除当前错误状态，累计失败数保留。退出时先停止业务，再在一秒预算内刷新与释放日志；整体退出仍受原有预算约束。终止性崩溃尽力刷新，队列不可用时使用独立应急 JSONL，单文件限制约 1 MiB，失败不阻断退出。

原生诊断页只查询当前运行的内存日志，支持级别、来源、模块和关键词组合筛选，复制当前筛选结果；清空仅影响内存。虚拟化列表保持滚动位置和选择，处于底部时跟随新增内容。自动刷新默认两秒一次，仅在诊断页可见时查询，可随时暂停。历史文件通过“打开日志目录”查看。

## 验证

日志专项测试覆盖并发顺序、隐私白名单、前端限流、来源授权、默认级别、队列溢出、故障恢复、分卷清理、释放和诊断页筛选。`NORI_CAPTURE_SETTINGS=1` 下运行 `NativeLoggingAndModelPopupVisualCapture` 可生成中英文 720×480 和 1920×1080 的诊断页、模型弹窗与确认窗口截图，默认输出至 `artifacts/native-settings/logging`。
