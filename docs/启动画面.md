# Nori 启动画面

## 使用

从发布包根入口 `Nori`（Windows 为 `Nori.exe`、macOS 为 `Nori.app`）启动。
“设置 → 常规 → 启动与窗口”中可关闭启动画面、选择 Photoshop、Android Studio、Microsoft 365、旧版 Office、IslandOnTop、ALLS 或简约布局，或填写本地背景图片的绝对路径；下次启动生效。

Photoshop 的右侧作品区、Android Studio 的左侧背景区支持自定义 PNG、JPG、JPEG、WebP 背景，最大 16 MiB；不支持网址和 UNC 路径。留空或图片失效时保持作品区留白。其他主题只显示启动信息与 Nori Logo。IslandOnTop 在工作区顶部居中显示；ALLS 为全屏布局，仍可用“隐藏”收起，不会退出主程序。
快速启动时会跳过画面，不为动画额外等待；“隐藏”只收起启动画面，不取消应用启动。
直接运行 `dotnet run --project Nori.Desktop` 不经过 Launcher，因此不展示独立启动画面。

## 结构

- `Nori.AppLauncher` 保留现有部署槽选择、旧进程等待和退出码传递，没有 Avalonia 依赖。
- `Nori.SplashHost` 随不可变部署槽发布，与 Desktop 共用相同版本的 Avalonia 运行库。macOS 下与 Desktop 一同位于 `Nori.Desktop.app/Contents/MacOS`。
- Launcher 为每次启动生成随机管道名，通过环境变量传给 Desktop，并把管道名、Desktop PID 和启动时间传给 SplashHost。
- Desktop 后台发送单向 JSON 行消息：本地存储、数据库、服务、插件发现、窗口准备和就绪。进度是阶段权重，不是耗时预测；不把后台联网和插件入口完成作为窗口就绪条件。
- SplashHost 收到配置后延迟 450 ms 展示；收到就绪、禁用、管道断开、Desktop 退出或达到 90 秒展示上限时退出。Desktop 出错时先撤下启动画面，由现有错误窗口负责提示。
- 管道限定当前用户；只传阶段与外观。Desktop 清除管道环境变量，不将它传给后续子进程。数据仍只由现有数据库存储，不增加根目录或系统目录配置。
- SplashHost 缺失或启动失败不会阻断 Desktop，也不改变安全模式、单实例和槽回退逻辑。发布结构检查仍要求正式包包含 SplashHost。

布局参考 MoreSplashScreen 的 Photoshop 风格（左侧信息、右侧作品区与细分隔线），按当前屏幕工作区收缩窗口。代码独立实现，直接复用主程序的 Nori 主题令牌、Fluent 控件样式和字体；作品区保持留白，预留给后续画师作品，目前不展示立绘或占位素材；未引入 MoreSplashScreen 代码、依赖或素材，不新增启动主题插件 API。

## 手工验收

1. 发布后从根入口启动，确认首次启动向导或初始化窗口正常出现，启动画面自动退出；快速启动允许完全不展示。
2. 在常规设置切换各个布局、自定义背景、关闭开关后分别退出并重启；检查设置持久化，中英文设置文案正常。
3. 使用 720×480 与 1080p 桌面环境检查窗口可见、文本与按钮不裁切。
4. 删除或移动背景文件后启动，确认作品区保持留白；输入网络路径、非图片、超大文件时设置应提示错误。
5. 在应用已运行时再次启动，确认只激活已有窗口，不残留启动画面。
6. 使用 `--safe-mode` 启动，确认可进入本地修复界面，不因启动画面触发联网或 Live2D 自动加载。
7. 隐藏启动画面或临时移走 SplashHost 可执行文件，确认 Desktop 仍能启动；验收后恢复文件。
8. 在启动过程中退出 Desktop，确认启动画面随之退出；宿主返回码仍由 Launcher 传回。

原参考项目的旧版 Office 项为禁用状态，此处独立实现经典 Logo / 名称 / 底部状态布局；JetBrains IDEs 和 dotUltimate 在参考项目中没有可用实现，不列为已支持样式。

按请求不新增或运行单元测试；现有发布结构测试仅补齐 SplashHost fixture 文件。
