# Nori Desktop 技术地图

## 1. 模块边界

| 模块 | 实现 | 当前职责 |
| --- | --- | --- |
| 稳定入口 | `Nori.AppLauncher`（程序集/入口 `Nori`） | 选择已提交部署槽、校验 manifest/RID/入口并转发参数；不更新、不删槽、不持有单实例锁 |
| 宿主 | .NET 10 + Avalonia 12 | 生命周期、四窗口、托盘、NativeWebView、原生伴侣视窗和桥接装配 |
| 核心 | `Nori.Core` + SQLite | 配置、聊天、记忆、技能、MCP、资源校验、HTTP 客户端、语音服务和平台能力 |
| 前端 | Vue 3 + TypeScript + Vite + UnoCSS | 首次运行、初始化、主控制台、设置、聊天和状态投影 |
| 桥接 | `NoriBridge` + `BridgeCommands` | JS→C# 命令相关性、权限、双层 JSON envelope 和宿主事件 |
| 资源服务 | `AssetServer` + Kestrel | 回环提供 `wwwroot`、本地资源和一次性音频/录音媒体端点 |
| 伴侣渲染 | `PetWindow` + `PetGlControl` + `Live2DCSharpSDK` | 原生 OpenGL ES 2.0、透明窗口、动作/表情/行为和交互 |
| 设置预览 | PixiJS + `pixi-live2d-display` | 只负责同源本地模型的视觉预览，不承担伴侣视窗真相 |
| 语音 | `VoiceService` + WebView 音频宿主 | C# HTTP TTS/Whisper；`main` WebView 用 WebAudio/MediaRecorder 播放和录音 |

## 2. 启动路径

`App` 只做装配：

1. `Program` 解析参数、确定包根并在单实例锁后调用 `StorageBootstrapper`；新数据只写包根 `data/`，失败不回退系统目录。
2. `AppStoragePaths` 固定 `core/database`、`core/security`、`knowledge/documents`、`resources/installed`、`plugins`、`webview/cache/host` 和 `diagnostics/logs`，有效 `.nori-storage.json` 优先；应用不读取旧版 Tauri 数据目录。
3. 打开 `nori.db`，初始化默认配置并拒绝比当前程序新的 schema。
4. 探测平台 NativeWebView：Windows 为 WebView2，macOS 为 WKWebView，Linux 为 WebKitGTK。
5. 启动 loopback `AssetServer`，生产页面从同源 `/{secret}/app/` 提供。
6. 创建 `first-run`、`init`、`main` 和 `pet`；WebView URL 带 `?window=<label>`。
7. `first_run_completed` 为 false 时显示 `first-run`，否则显示 `init`。

首次运行向导完成后，宿主写入完成标记、切换窗口并发送 `nori:init-start`。`InitView` 先订阅再调用 `init_ready`，用 pending 标记处理 WebView 加载晚于广播的情况。

## 3. 版本、安全模式与可诊断性

产品版本由 GitHub Actions 的 Release 输入控制；普通 CI/PR/手动构建未注入版本时精确为 `Dev`。Release 使用手动 codename，且数字版本不得由另一个发布标签重用，避免固定 revision 0 的槽发生覆盖；稳定标签使用 `v<version>-<codename>`，Sentry release 使用数字 `<version>`，程序 informational version 追加当前短提交 hash。CLR/File/NuGet 元数据保持数字版本；`ProductVersion.Current` 会保留完整 informational 字符串并进入 runtime snapshot、Smoke readiness、诊断信息、Crash 报告和 MCP `clientInfo`，`config.app_version` 仍是安装记录字段。

`--safe-mode` 只接受人工命令行启动，不做自动崩溃恢复。它保留 Web UI、日志、诊断导出和本地手动修复入口，跳过 MCP 自动连接、Proactive、Reflection、知识索引/记忆后台维护、AI 伴侣交互以及 Live2D 模型自动加载；Bridge 入口同时拒绝交互式联网、Provider/MCP/语音外部操作。Smoke 使用独立 profile，`readiness.json` schema v2 会报告产品版本、数据库/配置 schema 和 safe-mode 状态。

主窗口的 `export_diagnostics` 在后台生成大小受限的 ZIP：仅包含版本/平台/能力、脱敏日志和有界 Agent 阶段/Token/延迟元数据。数据库、配置、聊天/记忆/提示词、工具参数/结果、请求正文、录音、资源、凭据和真实数据路径均不进入白名单。`AgentTraceCollector` 是线程安全有界内存收集器，API 结构上不接受正文。

Provider 连接测试发送固定短探测，不保存配置、聊天或记忆；结果只返回 success/provider/latency/category/message，并对异常统一脱敏。`AgentEvaluationTests` 通过注入确定性适配器验证主回路、用量 Trace 和无正文边界，不依赖真实 Provider 或硬件。

## 4. 资源与模型边界

资源根目录为：

```text
<PackageRoot>/data/resources/installed/live2d/<model-id>/
```

发布包根目录由稳定 `Nori` launcher 选择 `app-<numeric-version>-<revision>` 槽；每个槽含 `deployment.json` 和 `wwwroot`，根目录 `.current` 只提供 current 优先级。`data/` 永不随发布包分发。

当前产品模型列表固定为：

- `arg-nori`
- `nori`

`ResourceManager` 只检查、列出、删除和从本地 ZIP/目录安全导入资源；`ZipExtractor` 拒绝绝对路径、UNC、盘符、`..`、控制字符和符号链接，并在 staging 完成验证后交换目录。没有远程 downloader、CDN、网关签名 URL 或模型更新服务。发布 ZIP 也不宣称携带可下载模型。

Native 伴侣视窗使用 Cubism Core 原生库；设置页的 Pixi 预览使用同源 `nori-assets`。Vite 必须保持 `base: "./"`，否则随机 AssetServer 前缀会被绝对资源路径绕过。

## 5. Bridge 与线程

前端只使用 `src/services/host/` 与 `src/services/runtime/`，不直接操作 `window.__nori`。宿主端命令必须：

- 在 `BridgeCommands.InvokeAsync` 的 switch 中注册；
- 由窗口 label 做权限校验；
- 在 `BridgeCommands` 中提供中文 `///` 调用说明；
- 将失败作为可读异常返回前端。

HTTP、SQLite、解压和网络请求不得堵塞 UI 线程；窗口、WebView `InvokeScript` 和宿主事件必须回到 Avalonia UI 线程。

AssetServer 的媒体端点使用一次性 token：TTS `GET` 取走即删，录音 `POST` 回传并有过期时间；音频数据不塞进 JSON bridge。`main` 是唯一音频宿主，关闭时只隐藏，因此播放状态不会在多个 WebView 间分裂。

## 6. 配置与秘密

配置表仍是 SQLite key/value，存储值为文本但读取时会重新推断布尔、整数、JSON 或字符串。模型显示设置优先使用 `<base>_<model-id>`，同时保留旧的全局键回退。

秘密字段（`*_api_key`、`*_secret`、`*_token`、`*_password`）的当前格式为：

```text
nsec2:<base64(nonce(12) | ciphertext | tag(16))>
```

这是 AES-256-GCM。主密钥由平台密钥库保存：Windows 使用 DPAPI 包裹文件，macOS 尝试 Keychain，Linux 尝试 libsecret；失败时使用权限收紧的文件回退。旧 `enc:dpapi:` 仅在 Windows 读取兼容，其他平台报告该项不可读并要求用户重填，不会清空其他设置。

静态加密只保护“单独拷走数据库”的场景，不防同一用户权限下已经能读取应用目录的进程。

## 7. Live2D 透明窗口现状

伴侣窗口为 Avalonia `WindowDecorations=None`、透明背景、`TransparencyLevelHint=[Transparent]`，内容是原生 `OpenGlControlBase`，不是 WebView 内的透明画布。宿主约 10Hz 从 alpha 画面生成贴近可见模型尺寸的连续外接矩形；Windows 使用 `WM_NCHITTEST` 查询该矩形，Linux X11 使用矩形输入形状，macOS 按当前光标是否位于矩形内切换忽略鼠标；Wayland 没有必要的协议能力时降级为整窗可点。

Windows 透明验证已在实际环境完成：

- Windows 10 19045 x64
- .NET 10
- Avalonia 12.1.1
- Avalonia.Controls.WebView 12.1.0
- WebView2 Evergreen

验证观察到窗口空白区域透出背景、模型区域正常绘制，且不需要 ExperimentalOffscreen。这个结论是 Windows 宿主验证，不应写成三平台都已完成桌面透明验收。

## 8. 发布与 CI

CI 的四道门是：

```text
pnpm build
pnpm test
dotnet build Nori.slnx
dotnet test Nori.slnx --no-build --no-restore
```

另外有一方 TODO/FIXME 扫描。扫描只覆盖 `Nori.Core`、`Nori.Desktop`、测试和前端源码；`Live2DCSharpSDK.*` 外部移植代码、generated/bin/obj 和 docs backlog 不作为产品 TODO。

正式 release 的平台口径：

- 槽式结构：Windows 根目录为 `Nori.exe`、`.current` + `app-*`；Linux 为 `Nori`、`.current` + `app-*`；macOS 为外层 `Nori.app`、`.current` + 槽内 `Nori.Desktop.app`。归档包含完整 root，运行时 data 严格在 `<PackageRoot>/data`；`<PackageRoot>` 必须可写且整包可移动，launcher 仅负责选择和启动。

- Windows：发布 blocker，生成 framework-dependent `win-x64` ZIP，必须有 ASP.NET Core Runtime 10 和 WebView2；不生成安装器、自包含包或签名。
- macOS/Linux：生成并上传 framework-dependent 槽式 tar.gz/ZIP，结构门禁与 Windows 相同。
- Windows ZIP 必须通过可执行文件、`wwwroot/index.html`、Cubism Core、ZIP 解压内容、SHA-256、CycloneDX SBOM、第三方清单和 `first-run`/`initialized` 启动冒烟。
- release workflow 在所有测试通过后才创建标签，并在标签之后才创建 GitHub Release。

发布前需显式确认 `Avalonia.Controls.WebView` 与 Cubism Core 的分发许可。清单对未确认条目保留 `license: null`，不根据包名猜测许可证。

## 9. 软件自动更新

客户端支持从 GitHub Release 自动检查并安装新版本槽：

- **更新源与过滤**：默认源为 `MF-Dust/Nori-Desktop-Pet`，仅拉取 `prerelease == false` 的正式发行版。开发环境 (`Dev`)、安全模式 (`--safe-mode`)、不支持的系统架构或未通过 Nori 启动器启动时，自动更新入口与后台调度强制禁用 (fail-closed)。
- **发布清单 (`UPDATE-{rid}.json`)**：CI 在产物打包阶段生成并附于 GitHub Release 资产中，包含 `schema_version`、`product_version`、`numeric_version`、`revision`、`rid`、`entrypoint`、`size_bytes`、`launcher_protocol`、`download_url`、`sha256` 等元数据。
- **严格网络安全**：
  - 强制仅使用系统默认安全 TLS (TLS 1.2/1.3)，禁止继承 `allow_insecure_tls`；
  - 严格限制 HTTPS 协议，且主机必须在严格白名单中 (`api.github.com`、`github.com`、`objects.githubusercontent.com`、`release-assets.githubusercontent.com`)；
  - API 与下载路径强制限定在当前仓库内；遇到 HTTP 403/429 频控时直接报错，绝不走旁路直链降级；
  - 有界防护：元数据响应上限 1 MiB，安装包体积上限 512 MiB，数据流 60 秒无数据读取空闲超时，总下载超时 30 分钟。
- **下载、解压与完整性校验**：
  - 下载阶段边读边流式计算 SHA-256 并实时汇报进度，实际大小或哈希不匹配立即中断并清理临时文件；
  - 解压阶段拒绝路径穿越、UNC、盘符、控制字符与重复路径，限制单文件最大 512 MiB、总展开最大 1024 MiB；
  - 提取并校验槽内 `deployment.json`，要求与 UPDATE 清单声明完全一致，严格拒绝当前槽或降级版本。
- **防竞态槽暂存与原子提交**：
  1. 解压进入 `<PackageRoot>/data/updates/staging/<uuid>` 隔离目录；
  2. 若目标槽已存在，禁止移至 `.destroy` 或覆盖（防止破坏正在运行的实例），仅当其已完全就绪且校验通过时复用；
  3. 关键防竞态：在新槽重命名之前，必须先验证当前运行槽名，并通过 `.current.tmp` 原子锁定当前 `.current` 指针，彻底消除新槽目录出现后与指针写入间的选择空窗；
  4. 将新槽移入 `<PackageRoot>/app-<version>-<revision>.partial`，校验 entrypoint 后原子重命名为目标槽名；
  5. 新槽就绪后，通过 `.current.tmp` 原子重命名切换 `.current`。
- **并发控制与主动取消**：检查与安装经由 `SemaphoreSlim` 互斥保护候选状态；通过 `updater_cancel` 支持随时取消正在执行的检查或下载任务；`Dispose` 时只释放自身拥有的网络客户端。
- **后台调度与平滑重启**：
  - 后台自动调度器启动 30 秒后执行首检，之后每 24 小时检查一次，持久化记录 `update_last_checked_at`；发现新版本时作废快照并向 WebView 广播非阻塞通知；
  - 桥接命令统一为 `updater_check`、`updater_install`、`updater_cancel`、`updater_restart`，`ui_get_snapshot` 中统一包含 `updater` 快照状态；
  - `updater_restart` 时宿主进程拉起稳定启动器，传递原生 `--launcher-wait-pid <pid>` 与 `--launcher-wait-start-ticks <ticks>` 参数后平滑退出，启动器等待旧进程退出后根据 `.current` 选择并拉起新槽。
