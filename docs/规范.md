## 总体原则

1. **一致优先**：改代码前先看同目录已有文件的风格，沿用现有 helper、生命周期和错误处理。
2. **模块职责单一**：入口只做装配；业务逻辑放在对应的 Core、Desktop、PluginRuntime 模块。
3. **原生窗口优先**：用户窗口、设置、记忆、模型管理和桌宠都由 Avalonia 原生窗口负责。WebView 只用于隐藏音频宿主和受控插件页面。
4. **少写代码**：优先复用已有类型、标准库和平台能力；不要为单一实现添加 speculative interface、factory 或配置层。
5. **安全边界不能省略**：输入验证、路径 containment、秘密保护、响应大小限制和可访问性属于功能要求，不是可选优化。

## 通用代码风格

- 缩进使用 Tab，换行使用 LF，TypeScript、C# 和配置内字符串优先使用双引号。
- 中文用于注释、日志和用户可见宿主错误；代码标识符按各语言惯例命名。
- C# 文档注释使用 `///`；桥接命令的注释必须包含前端调用示例。
- 不提交调试探针、临时脚本、日志、构建产物或未解决的 TODO/FIXME。

## 前端 TypeScript 音频宿主

`app/desktop/src` 不承载用户界面。当前只包含非原生音频后端使用的隐藏 `audio-host` 页面、WebAudio/MediaRecorder、宿主事件和类型化 bridge 客户端。

- `src/bootstrap.ts` 是音频宿主页入口；用户窗口由原生 Avalonia 提供，不在音频宿主中添加页面 UI。
- 音频状态调用经过 `src/services/host/` 的类型化接口；结构化错误日志经过 `src/services/runtime/logging.ts`，不直接读取 `window.__nori`。
- 音频页面只加载宿主生成的同源资源 URL；Vite 必须保持 `base: "./"`，以兼容 AssetServer 的随机路径前缀。
- `src/assets/style/tokens.ts` 是原生 Avalonia 主题的令牌来源，修改后运行 `pnpm theme:check`；`pnpm test` 同时检查原生主题对比度。
- TypeScript 局部常量使用 `UPPER_SNAKE`，局部变量使用 `camelCase`；日志只传递固定事件名和已知错误类型，不记录异常正文。
- 前端测试使用 Vitest；按 `AGENTS.md` 的 Local Verification 根据改动范围执行检查。

## 后端 .NET 10 / Avalonia / C#

- `Nori.AppLauncher` 是无 Avalonia 依赖的稳定根入口，只选择并校验 `app-<numeric-version>-<revision>` 部署槽，不负责更新、删除槽或单实例锁。
- `Nori.Core` 保持 Avalonia 无关，承载配置、数据库、资源、网络、聊天、记忆、语音、安全和平台抽象。
- `Nori.Desktop` 负责 Avalonia 窗口、托盘、原生 Live2D、音频装配、桥接和宿主生命周期；`App.cs` 只做装配。
- `Nori.Desktop/Windows` 的用户窗口是原生 Avalonia：`first-run`、`init`、`main`、`pet` 以及按需打开的设置、记忆、模型、聊天和快捷聊天窗口。关闭通常隐藏而不是销毁。
- 原生设置页位于 `Nori.Desktop/Settings` 和 `Settings/Pages`，双语资源与控件状态由宿主管理；不要把设置页回退到前端页面。
- `PetWindow` 使用 `PetGlControl` 和 `Live2DCSharpSDK` 直接渲染 OpenGL ES 2.0。命中测试、平台降级和模型预览遵循 `IPlatformServices.Capabilities`，不能硬编码 Windows 能力。
- Bridge 命令使用 verb-first `snake_case`，必须在 `BridgeCommands.InvokeAsync` 的 switch 中注册。audio-host 允许命令见 `src/services/host/commands.ts`；原生窗口经各自服务白名单调用。失败抛出可读中文异常，不返回静默 null。
- HTTP、SQLite、文件解压和网络请求不得阻塞 UI 线程；窗口操作和 `InvokeScript` 必须回到 Avalonia UI 线程。
- 插件是受信任的进程内 .NET 扩展，不是安全沙箱；插件 WebView 只能使用宿主生成的绝对资源 URL、当前插件 web 根和受限 bridge。
- 增加分支、循环、解析器或安全逻辑时，留下一个最小可运行测试；不要为简单 getter 添加无价值测试。

## 配置文件与数据库

- 新数据只能写入 `<PackageRoot>/data`，由 `AppStoragePaths` 管理。数据库为 `core/database/nori.db`，秘密为 `core/security/secret.key`，资源、插件、WebView 缓存和诊断日志使用固定子目录。
- 数据初始化必须在单实例锁后完成；无有效 marker 的非空存储目录 fail closed；staging 失败只能清理 staging。
- SQLite `config` 表的 key 使用 `snake_case`。前端不读写通用 `get_config`/`set_config`，由类型化宿主命令校验并持久化领域设置。
- API key 等秘密只写不读；快照、事件、错误和日志只能返回 `hasApiKey` 等状态，不得回传明文。
- 敏感配置使用 `nsec2:<base64(nonce | ciphertext | tag)>` AES-256-GCM。主密钥优先使用平台密钥库，文件回退必须保持 0600 或平台等价权限，并使用共享锁防止跨实例首次创建竞态。
- 出站响应必须使用现有的大小受限读取 helper；流式协议同时限制原始字节、单帧和累计文本，不能直接 `ReadToEnd`。

## 提交与验证

- 提交格式：`<type>: <short description>`，例如 `fix: 修复原生设置错误本地化`。
- 改动保持聚焦，不混入无关重构；文档必须反映当前原生窗口和隐藏音频宿主架构。
- 前端改动通常运行 `pnpm lint`、`pnpm build`、`pnpm test`；涉及覆盖率时运行 `pnpm coverage`。
- 后端改动通常运行 `dotnet build Nori.slnx --configuration Release --no-restore`，以及对应项目的 `dotnet test ... -m:1`。
- 发布或工作流改动至少解析 YAML，检查所有第三方 Action 使用不可变 commit SHA，并运行 `git diff --check`。
- 视觉改动按 `AGENTS.md` 要求检查 720×480 和 1080p；原生设置改动还应覆盖中文和英文资源路径。
