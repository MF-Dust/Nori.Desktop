## 总体原则

1. **一致优先**: 改代码前先看同目录已有文件的风格, 跟着已有风格走.
2. **本地化命名**: 业务概念用可读命名, 常量用 `UPPER_SNAKE`, 变量用 `camelCase`, 导出的方法 / 类型等用 `PascalCase` (见各端分节).
3. **模块职责单一**: 一个文件只做一件事, 类同的文件放到同一目录.
4. **不要塞大文件**: `App.cs` / 入口文件只做装配, 业务逻辑拆到独立模块 (`BridgeCommands`/`ConfigStore`/`ResourceManager`/`FileLogger` 等).
5. **减少魔法数字/字符串**: 可复用的常量抽出去 (如配置键 / 步骤数).
6. **解耦! 解耦! 解耦!**

---

## 通用代码风格

- **缩进用 Tab** (不是空格), 项目源码 `.ts/.vue/.cs/.less` 均为 Tab 缩进.
- **换行**: LF, Windows 下 Git 会做 CRLF 转换警告, 属正常.
- **字符串**: 前端统一双引号优先 `"`; C# 同样用 `"`.
- **注释**:
  - 前端用 `//` (组件内块注释同), 有导出的方法 / 类型等时, 用 `/**` 文档注释.
  - C# 用 `///` 文档注释 (给桥接命令写前端调用示例), `//` 行内注释.

## 前端(Vue 3 + TypeScript + UnoCSS)

### 组件与命名

- 组件统一用 **`<script setup lang="ts">`**.
- **文件命名**: PascalCase, 如 `LanguageSelect.vue`/`LlmConnect.vue`.
- **组件放对目录**:
  - 页面级: `src/views/*.vue`
  - 向导步骤组件: `src/components/*.vue`
- 局部常量用 `UPPER_SNAKE` (如 `CONFIG_KEY`/`STEPS_COUNT`/`KEY_BASE`), 局部变量用 `camelCase`.
- 导出的方法 / 类型等用 `PascalCase`.

### 样式与单位

- **原子类优先**: 组件样式一律写 UnoCSS 原子类, **不要新增 `<style scoped>`**. 配置见 `uno.config.ts`(`presetWind3`, 不带任何 reset).
- **单一色源**: 设计令牌定义在 `src/assets/style/tokens.ts`; `uno.config.ts` 的主题、`naiveOverrides.ts` 的 naive 覆盖、`theme.less` 的 `:root` 三处全部派生自它. 改配色只改 `tokens.ts`, 三处一致性由 `tests/theme/tokens-sync.test.ts` 看守.
- **全局样式只保留三类**(都在 `src/assets/style/theme.less`): 基础重置与根字号、`:root` 令牌、关键帧/滚动条/Vue 过渡类/`.chat-markdown` 排版. 其他一切进原子类.
- **长度单位一律 rem**: 根字号 `62.5%`(即 `1rem = 10px`), Uno 间距刻度按 4px 网格(`1` = `0.4rem`). **不要出现 `px`**; 非刻度值用任意值语法 `w-[6.8rem]`.
- **颜色只用令牌**: `text-text-muted` / `bg-bg-card` / `border-line-subtle` / `bg-nori-teal-bright/8` 这类, **不要写裸 hex**(唯一例外是 `tokens.ts`).
- **最小字号 `text-xs`(1.15rem)**: 更小的字在深色玻璃上不可读, 由 `tests/style/conventions.test.ts` 拦住.
- **文字色用 `--danger-text`**, `--danger` 只用于填充与描边(纯 `#fb3c44` 当文字在浅面板上不达 4.5:1).
- **对比度门禁**: 前景 × 背景组合要 ≥ 4.5:1(大字/加粗 ≥ 3:1), 由 `tests/theme/contrast.test.ts` 表驱动校验.
- **UnoCSS 是静态扫描**: 类名必须在源码里字面出现. **禁止用模板字符串拼类名**(`` `bg-${x}` `` 不生效), 动态样式写成三元里的完整字面类名.
- **复用 shortcuts 而不是复制长串**: `glass-panel` / `surface-card` / `scroll-area` / `glow-teal` / `title-lg|md|sm` / `text-sub` / `text-hint` / `mono` / `focus-ring` / `btn-primary|ghost|danger|icon|close` / `chip|chip-teal|chip-success` / `field` / `field-label` / `input-base` / `nav-item` / `nav-item-active`. 新的重复形态先加 shortcut.
- **复用 UI 原子组件**: `src/components/ui/` 下有 `AppButton` / `AppCard` / `AppChip` / `AppField` / `AppSwitchRow` / `AppEmpty` / `AppSkeleton`, 能用就不要重造.
- **naive-ui 的外观只经 `naiveOverrides.ts` 调**: 它的样式是运行时注入的 CSS-in-JS, 注入顺序不受我们控制, **不要用原子类去覆盖 naive 内部 DOM**(外层包一个 div 加布局类可以).
- 布局: 窗口最外层用 `w-100vw h-100vh`, 内部子层用 `flex`/`grid` 与 `min-h-0`, **不要用 `position: absolute` 做页面布局**; 滚动容器配 `flex-1 min-h-0` + `scroll-area`, 避免 `height: 100%` 与 flex 混用导致内容被裁切.
- **弹窗与 Live2D 舞台响应式**: 严禁在模态弹窗或预览容器中硬编码固定大高度(如写死 `h-[50rem]`), 必须采用 `max-h-[calc(100vh-...)]` 配合 `aspect-[3/4]` 等自适应比例, 保证在 720×480 最小分辨率与系统 DPI 缩放下不溢出、不产生纵向多余滚动条.
- **动态列表与表情/选择器容器保护**: 包含较多可选项目的药丸组(如 Live2D 表情列表)必须添加 `max-h-[16rem] overflow-y-auto scroll-area` 滚动保护, 并通过 `watch` 深度响应 `modelId` 与初始状态变更, 避免小分辨率下内容被挤压裁剪或异步数据丢失.
- 所有可交互元素都要键盘可达: `<button type="button">` + `focus-ring`; 图标按钮补 `:aria-label`.

### 状态与数据

- 用 `ref` / `computed`(不要在 `<script setup>` 里用 `reactive` 存整个对象除非确实需要).
- 业务状态与配置统一经 `src/services/runtime/index.ts` 的 typed API 读写; 组件不得直接调用通用配置命令, 也不得持有业务真相。
- 异步组件挂载里读配置用 `onMounted(async () => { ... })`, 不要把未捕获异常抛出成界面崩溃.
- **失败必须让用户看见**: 走 `src/services/feedback/` 的 `feedback.error(可读中文, error)`; `console.error` 只作诊断, 不再是唯一出口.
- 输入类配置写入用 **防抖**: 400ms, 每字段独立计时器, 卸载时自动 flush, 暴露 `saving/saved/error` 供 `AppField` 显示「已保存」.
- **防抖注意**: 每个输入字段必须用**相互独立的 timer**, 不要多个字段共用一个 timer__否则先输入字段的定时器会被后输入字段的 `clearTimeout` 取消, 导致先输入的那份配置丢失不落库.
- **设置页读快照**: 只同步「用户没在编辑」的字段, 避免一次性 `synced` 导致的陈旧, 也不会吞掉正在输入的内容.
- **平台相关 UI 一律读 `RUNTIME.platform()`**(`supportsGlobalCursor` / `supportsWindowDrag` / `supportsHitThrough` / `supportsTray` 等), 不要硬编码 Windows 假设, 也不要靠 `try/catch` 静默吞掉 `PlatformNotSupportedException`.
- 频繁输入/频繁变化的 UI 用 `v-model` 绑定 `ref`.

### 国际化(i18n)

- 文案按语言放: `src/services/i18n/locales/*.ts`.
- 读取文案统一通过 `useLanguages()`(来自 `src/services/i18n/useLanguages.ts`), 按 `components.firstRun.xxx` / `views.firstRun.xxx` 分层.
- **组件里文案要用 `computed(() => useLanguages().components.firstRun.xxx)`**, 让文案随 `locale` 响应式更新(不要做成一次性快照常量).
- **新增文案要改三处**: `locales/zh-CN.ts` + `locales/en-US.ts` + `useLanguages.ts` 的访问器树. 键集合一致性与访问器覆盖率由 `tests/i18n/completeness.test.ts` 看守.
- **`<template>` 里不允许出现中文字面量**(注释除外), 同一个测试会拦住. 需要拼数字/变量时拆成「变量 + 标签」两段, 不要在 i18n 值里放 `{}` 占位符.
- 语言切换调用 `useLanguage.setLanguage(code)`(`src/services/i18n`); 跨窗口同步由 `RUNTIME.onLanguageChanged` 在各窗口重放.

### 图标

- 图标数据集中在 `src/services/icon/index.ts` 的 `icon` 对象, 用 `satisfies Record<string, IconData>`, 自动获得类型与 `IconName`/`allIcons`.
- 使用 `<Icon name="..." mode="..." class="..."/>`(`src/components/Icon.vue`, props: `name/mode/size/strokeWidth`).
- 新增图标就在 `icon` 里加一个 entry(写 `// 说明`), 也可写 `stroke` 或 `fill` 路径(24x24 viewBox).
- 图标尺寸用 rem 或 `:size` 控制, 不要散落写死像素.
- **外部数据(技能/MCP)的 icon 字段先过 `resolveIconName()`**, 未知名称会 fallback, 不至于一个脏数据拖崩整页.

### 路由与窗口

- 路由集中在 `src/services/router/index.ts`; `/` 默认转发到 `/init`.
- 窗口 label → 路由的映射写在 `src/services/window/index.ts` 的 `WINDOW_ROUTES`, 每个 webview 挂载后自行 `ROUTER.replace` 到对应路由.
- 窗口 label 由宿主通过 URL 查询参数 `?window=<label>` 注入, 前端同步可读, 不需要往返.
- **宿主能力一律走服务层**: 业务命令经 `src/services/runtime/` 的 typed API, 窗口/事件/错误等 UI 适配经 `src/services/host/` 与 `src/services/window/`; 不要直接摸 `window.__nori`. Pixi 预览只允许同源资产加载与视觉渲染。
- 窗口切显隐由宿主端 `complete_first_run` 控制(写 `first_run_completed` 标记 + hide/show 窗口); 前端首次运行只发送用户选择与完成意图。

## 后端(.NET 10 / Avalonia / C#)

- **项目划分**:
  - `Nori.Core`: 不依赖 Avalonia 的纯逻辑, 可单测. 按职责分目录 `Data`/`Configuration`/`Resources`/`Assets`/`Chat`/`Logging`/`Platform`, 一个文件只做一件事.
  - `Nori.Desktop`: Avalonia 宿主. `App.cs` **只做装配**(起服务/建窗口/挂托盘/决定首启走向), 不要往里塞业务.
  - `Nori.Desktop/Bridge`: `NoriBridge` 只管消息收发, 命令实现放 `BridgeCommands`.
  - `Nori.Desktop/Windows`: 四窗口定义与生命周期.
  - `Nori.Desktop/Tray`: 系统托盘.
  - `Nori.Core/Platform`: 每个实现一个文件 (`IPlatformServices` / `WindowsPlatformServices` / `UnsupportedPlatformServices`).
  - `Nori.Core.Tests`: xUnit. 纯函数(配置类型推断/路径安全/ZIP 校验/动作标记)必须有用例, 这些地方出错不会崩, 只会静默错.
- **缩进同样用 Tab**, LF, 双引号, 注释与文档注释一律中文.
- **命名**: C# 沿用语言惯例 —— 类型/方法/属性/常量用 `PascalCase`, 局部变量 `camelCase`, 私有字段 `_camelCase`. **不要把前端那套 `UPPER_SNAKE` 局部常量约定套到 C# 上**, 两端各随各自生态.
- **桥接命令命名**: 保持 `snake_case` 且动词开头(`ui_get_snapshot`/`settings_update_ai`/`chat_start`/`window_show`), 与 `src/services/runtime` 的 typed API 完全一致 —— 这是跨语言契约, 不随 C# 命名习惯改.
- **每个桥接命令加 `///` 文档注释, 写出前端调用示例**(如 `invoke("ui_get_snapshot")` / `invoke("settings_update_ai", {...})`), 与原来 Rust 侧的要求一致.
- **命令失败一律抛异常**, 消息就是给用户看的中文文本; `NoriBridge` 会统一转成前端的 reject. 不要在命令里吞异常后返回 null.
- 新增命令后**记得在 `BridgeCommands.InvokeAsync` 的 switch 里注册**, 否则前端调用会得到"未知的命令".
- 阻塞操作(HTTP/解压/SQLite)不要放在 UI 线程; 需要碰窗口或 `InvokeScript` 时用 `Dispatcher.UIThread`.
- 平台相关调用(Win32 P/Invoke 等)一律收敛到 `Nori.Core/Platform/IPlatformServices`, 不要散落到别处.
- 依赖新增要合理,优先选用仍在维护的高Star项目.

## 配置文件与数据库

- 启动入口固定为无 Avalonia 依赖的 `Nori.AppLauncher`（程序集/稳定根入口 `Nori`）。它只选择并校验 `app-<numeric-version>-<revision>` 槽，不负责更新、删除槽或单实例锁。
- 新数据只能写入 `<PackageRoot>/data`，由不可变 `AppStoragePaths` 提供 containment 校验；无法创建或写入时必须明确失败，不得回退系统目录。数据库位于 `core/database/nori.db`，秘密位于 `core/security/secret.key`，知识文档位于 `knowledge/documents/Memory.md`，资源位于 `resources/installed`，插件、WebView、自动化和诊断使用各自固定子目录。
- 新数据初始化必须在单实例锁后完成：目标有效 marker 优先；非空无 marker fail closed；staging 失败只清理 staging。
- 数据库 `config` 表的 key 仍用 **`snake_case`**: 如 `first_run_completed`/`selected_model`/`language`/`llm_api_base`/`llm_api_key`/`llm_model`.
- 前端不再读取通用 `get_config` 或写入通用 `set_config`; C# 通过 `ui_get_snapshot` 返回脱敏 DTO, 通过领域命令校验并持久化更新。
- `ConfigValue.FromStorage` 仍会在读取时重新推断类型, **改动前先看 `Nori.Core.Tests` 的用例**; 缩放/表情等模型配置必须保留按模型键与旧全局键的兼容回退。
- API Key 等秘密只写不读: 快照/事件/错误/日志只能返回 `hasApiKey` 等状态, 不得回传明文。
- 首次运行完成的标记用固定 key `first_run_completed`, 统一由 `ConfigStore.MarkFirstRunCompleted` 处理。
- 新增配置键由后端 runtime 统一映射与持久化, 前端 DTO 不暴露内部 key.

## 提交与改动原则

- 改动尽量**聚焦**: 一个任务改相关文件即可, 不要把无关重构混进来.
- 改完跑 `pnpm build`(前端 vue-tsc + vite)、`dotnet build`(宿主)与 `dotnet test`(纯函数用例)确保可编译可通过.
- 不在仓库留下临时文件(如调试探针脚本/`__probe*` 等), 用完清理.
- 调试用的 `console.log` 提交前移除, 仅在有意义的报错路径保留 `console.error`.
