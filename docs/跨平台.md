# 跨平台支持与验收口径

Nori 共享 .NET 10 + Avalonia 12 宿主和 Vue 前端；三平台均使用根 launcher、`.current` 与槽式 framework-dependent 包，Windows 仍是首要验收平台。

## 1. 平台矩阵

| 能力 | Windows x64 | Linux X11 | Linux Wayland | macOS |
| --- | --- | --- | --- | --- |
| NativeWebView | WebView2 | WebKitGTK | WebKitGTK | WKWebView |
| 当前 CI | 四道门 + 发布/ZIP/启动冒烟 | 编译 + FDD 发布 | 依发行环境 | 编译 + FDD 发布 |
| 正式发布资产 | framework-dependent ZIP（完整 root） | framework-dependent tar.gz（完整 root） | framework-dependent ZIP（完整 root） | framework-dependent ZIP（完整 root） |
| 本地槽预览结构 | 根 `Nori.exe` + `.current` + `app-*`，data 运行时创建 | 根 `Nori` + `.current` + `app-*`，data 运行时创建 | 根 `Nori` + `.current` + `app-*`，data 运行时创建 | 外层 `Nori.app` + `.current` + 槽内 `Nori.Desktop.app`，data 在 root 内创建 |
| .NET 前提 | ASP.NET Core Runtime 10 | ASP.NET Core Runtime 10 | ASP.NET Core Runtime 10 | ASP.NET Core Runtime 10 |
| 原生 WebView 前提 | WebView2 Evergreen Runtime | `libwebkit2gtk-4.1-0`、GTK | WebKitGTK/桌面环境 | 系统 WebKit |
| 原生伴侣 OpenGL | 支持 | 支持（依驱动） | 支持（依驱动） | 支持（依驱动） |
| 伴侣置顶 | 支持 | 支持 | 支持 | 支持 |
| 模型矩形点击穿透 | `WM_NCHITTEST` | X11 Shape 矩形 | 不支持，整窗可点 | 按光标切换忽略鼠标 |
| 全局光标 | 支持 | 支持 | 不支持，退化窗口内跟随 | 支持 |
| 窗口拖动 | 原生窗口拖动 | `_NET_WM_MOVERESIZE` | 能力标志驱动降级 | AppKit 拖动 |
| 托盘 | 支持 | 视 StatusNotifier 桌面 | 视桌面 | 支持 |
| 麦克风 | WebView/系统授权 | WebView/系统授权 | WebView/系统授权 | 需要 `NSMicrophoneUsageDescription` |

“支持”表示代码路径和能力抽象存在；发布归档仍需对应平台环境验收。发布说明不得把 framework-dependent 归档写成安装器或自包含包。

## 2. 能力驱动降级

平台能力来自 `IPlatformServices.Capabilities` 并进入 runtime snapshot，前端据此禁用或解释不可用功能：

- Wayland 没有稳定的全局光标和输入形状接口，伴侣视窗降级为整窗可点、窗口内跟随或拖动手柄。
- Linux 托盘安装失败时，`supportsTray=false`，主窗口提供内建入口；不静默吞掉失败。
- 非 Windows 的模型矩形输入形状更新失败时停止同步并保持整窗可点，不打断 OpenGL 渲染。
- 运行时不具备能力时不会以异常作为常规控制流；调用前先读能力标志。

## 3. 安全模式与诊断

`--safe-mode` 是三平台相同的人工启动开关，不依赖平台崩溃恢复机制。它保留 UI、日志、诊断 ZIP 和本地手动配置修复；MCP 自动连接、Proactive/Reflection、记忆后台维护、AI 伴侣交互和 Live2D 自动模型加载会被跳过，Bridge 入口也拒绝交互式联网、Provider/MCP/语音外部操作。Wayland 的能力降级仍由 `supportsHitThrough` 等快照字段决定，不会因安全模式改变平台声明。

连接测试和诊断导出都在宿主后台线程执行。连接测试不保存配置或内容；诊断 ZIP 只带脱敏、有界日志和 Agent 阶段/用量指标，不包含数据库、用户内容、请求体、录音、资源、凭据或真实路径。

## 4. 语音实现

语音不再依赖 Windows-only NAudio：

- C# `VoiceService` 选择 OpenAI、Custom HTTP、GPT-SoVITS HTTP TTS 和 Whisper STT。
- TTS 字节通过 AssetServer 一次性媒体 token 交给 `main` WebView。
- `main` 用 WebAudio 播放，并按 RMS 回传 `audio_level` 驱动嘴形。
- 录音使用 `MediaRecorder`，停止后 POST 回一次性媒体端点。
- macOS 的 `Info.plist` 由发布脚本写入 `NSMicrophoneUsageDescription`；NativeWebView 12.1.0 没有公开统一的 PermissionRequested 钩子，系统原生提示负责授权。

## 5. 数据和模型

正式运行数据只位于 `<PackageRoot>/data`，由不可变 `AppStoragePaths` 管理；不存在可写时明确失败，不回退系统目录。新布局包括 `core/database`、`core/security`、`knowledge/documents`、`resources/installed/live2d`、`plugins`、`webview/cache/host` 和 `diagnostics/logs`。首次启动会在单实例锁后将旧 Tauri 目录迁移；旧平台路径仅由 `LegacyDataPathResolver` 使用。

原 Tauri `app_data_dir()` 仅作为迁移源：

| 平台 | 目录 |
| --- | --- |
| Windows | `%APPDATA%/cn.erhio.noriDesktopPet/data` |
| macOS | `~/Library/Application Support/cn.erhio.noriDesktopPet/data` |
| Linux | `$XDG_DATA_HOME/cn.erhio.noriDesktopPet/data`，缺省为 `~/.local/share/cn.erhio.noriDesktopPet/data` |

Live2D 资源只在本地 `<PackageRoot>/data/resources/installed/live2d/` 管理。产品模型范围为 `arg-nori` 与 `nori`；没有模型 CDN、远程下载、网关、自动更新或随 release 下载模型的步骤。

敏感配置使用 `nsec2:` AES-256-GCM。旧 `enc:dpapi:` 只在 Windows 兼容；macOS/Linux 无法解密旧值时只要求重新输入对应密钥。

## 6. 构建与发布

开发/CI：

```bash
pnpm install
pnpm check:todo
pnpm build
pnpm test
dotnet build Nori.slnx --configuration Release
dotnet test Nori.slnx --configuration Release --no-build --no-restore
```

Windows 发布：

```cmd
publish.bat
```

它固定执行 `dotnet publish --self-contained false`，不提供 self-contained、安装器、签名或更新服务。正式 ZIP 的目标机必须自行安装：

1. Windows x64；
2. ASP.NET Core Runtime 10（包含应用所需的 .NET Runtime 与 Kestrel 共享框架）；
3. Microsoft Edge WebView2 Evergreen Runtime。

浏览器 DOM 自动化是可选能力，仅在 Windows 上可用；目标机还必须安装 Microsoft Edge stable。Playwright 只连接 `msedge` channel，使用临时隔离 profile，不会随 ZIP 捆绑或下载浏览器。自动化默认关闭，填写等高风险动作由主界面审批；未满足平台、开关或审批条件时入口 fail-closed。

CI 通过 `scripts/package-windows.ps1` 检查可执行文件、`wwwroot/index.html`、`Live2DCubismCore.dll` 和 framework-dependent 内容，再生成 ZIP、SHA-256、CycloneDX SBOM 与不猜测许可证的 `THIRD-PARTY-NOTICES`。`scripts/smoke-published.ps1` 会以临时 profile 启动 `first-run` 与 `initialized`，等待 JSON readiness 并强制有界退出。

macOS/Linux 的 `publish.sh` 生成与 Windows 相同的完整 root；Release workflow 当前发布 `linux-x64` 与 `osx-arm64`，归档整个 root（包括 launcher sidecars、槽和隐藏的 `.current`），不把 data、.NET runtime 或 source map 带入包。`<PackageRoot>` 必须可写且整包可移动。

## 7. 已知前提

- Windows 透明窗口的实际验证已完成；macOS/Linux 的能力表和编译门不替代桌面环境实测。
- Linux X11 与 Wayland 行为不同，XWayland 只有在存在可用 `DISPLAY` 时才按 X11 能力处理。
- Cubism Core 原生库必须与目标 RID 匹配；`linux-arm64` 没有仓库内官方库，不属于当前正式验收矩阵。
- Avalonia WebView 与 Cubism Core 的分发许可必须在 release workflow 中显式确认，未确认前不得把条目写成具体许可证。
