# 跨平台支持与验收口径

Nori 共享 .NET 10 + Avalonia 12 原生宿主；播放和录音走各平台声卡。三平台均使用根 launcher、`.current` 与槽式 framework-dependent 包，Windows 仍是首要验收平台。

## 1. 平台矩阵

| 能力 | Windows x64 | Linux X11 | Linux Wayland | macOS |
| --- | --- | --- | --- | --- |
| 音频播放/录音 | WASAPI | ALSA `default` | ALSA `default` | AudioQueue |
| 当前 CI | 四道门 + 发布/ZIP/启动冒烟 | 编译 + FDD 发布 | 依发行环境 | 编译 + FDD 发布 |

## 2. 能力驱动降级

平台能力来自 `IPlatformServices.Capabilities` 并进入 runtime snapshot，原生界面据此禁用或解释不可用功能：

- Wayland 没有稳定的全局光标和输入形状接口，伴侣视窗降级为整窗可点、窗口内跟随或拖动手柄。
- Linux 托盘安装失败时，`supportsTray=false`，主窗口提供内建入口；不静默吞掉失败。
- 非 Windows 的模型矩形输入形状更新失败时停止同步并保持整窗可点，不打断 OpenGL 渲染。
- 运行时不具备能力时不会以异常作为常规控制流；调用前先读能力标志。

### 原生背景模糊

“常规 → 外观 → 背景模糊”默认开启，自动保存至 `ui_background_blur_enabled`。关闭后立即恢复深色实底；系统不支持时也使用实底，但不修改用户偏好。普通应用窗口及自有独立对话框统一请求 `AcrylicBlur → Blur → Transparent`，仅实际获得 AcrylicBlur 或 Blur 时使用半透明窗口表面，普通透明不视为模糊成功。

Avalonia 12.1.1 的 Windows 路径由系统合成器提供 Acrylic；macOS 通过 NSVisualEffectView 的 BehindWindow 实现，深色外观由应用覆盖层保证；X11 路径仅在 KWin 开启合成时提供 Blur。窗口背景与整窗根容器不得再叠加不透明底色遮住已启用的效果。系统设置、渲染后端和桌面环境均可能改变可用效果。

桌宠保持透明，Quick Chat 保留局部材质，不开启整窗背景模糊；这保证气泡之间及角色周围的透明留白。不能仅凭用户开关假定模糊已生效，要看当前窗口实际拿到的材质。

视觉验收必须使用真实桌面与窗口后方的高对比图案，对照开启、关闭和不可用状态；Headless 截图只能证明控件布局，不能证明系统已模糊桌面。macOS/Linux 未经对应桌面实测时应明确报告，不以编译通过代替验收。

### 手动窗口扫描

Quick Chat 输入框旁的扫描按钮进入选窗模式：悬停显示绿色轮廓，点击窗口后播放扫描线并把该窗口的截图发送给当前聊天 AI（需要模型支持图片）。也可用 Tab / Shift+Tab 切换、Enter 选定、Esc 取消；点击空白区域取消。扫描期间不把点击传给下方应用；隐藏桌宠或关闭 Quick Chat 会取消操作并丢弃迟到结果。

分析读数逐字显示，30 秒后隐藏；减少动态效果时立即显示全文并固定扫描线。芯片容量为 5 次，每 5 分钟恢复 1 次；余量与最近 32 条内容指纹/读数只保存在进程内，输入框重建不重置，退出应用后清除。同一截图的缓存读数不重复请求 AI 或消耗余量。截图不落盘、不进入聊天历史，仅选定后发送给已配置的 Provider；受保护或无法截图的窗口会报告失败。安全模式禁止扫描，非 Windows 平台点击时明确说明不可用。

扫描像素字体沿用 Nori.Web 的 Fusion Pixel 12px Proportional SC（2026.07.01），仅从 WOFF2 转为 TTF 容器；版权与 SIL OFL 1.1 随包位于 `licenses/fonts/FusionPixel.OFL.txt`。

## 3. 安全模式与诊断

`--safe-mode` 是三平台相同的人工启动开关，不依赖平台崩溃恢复机制。它保留原生窗口、日志、诊断 ZIP 和本地手动配置修复；MCP 自动连接、Proactive/Reflection、记忆后台维护、AI 伴侣交互和 Live2D 自动模型加载会被跳过，Bridge 入口也拒绝交互式联网、Provider/MCP/语音外部操作。Wayland 的能力降级仍由 `supportsHitThrough` 等快照字段决定，不会因安全模式改变平台声明。

连接测试和诊断导出都在宿主后台线程执行。连接测试不保存配置或内容；诊断 ZIP 只带脱敏、有界日志和 Agent 阶段/用量指标，不包含数据库、用户内容、请求体、录音、资源、凭据或真实路径。

## 4. 语音实现

语音不再依赖 Windows-only NAudio，也不再经过页面播放：

- C# `VoiceService` 选择 OpenAI、Custom HTTP、GPT-SoVITS HTTP TTS 和 Whisper STT。
- Windows 用 WASAPI，macOS 用 AudioToolbox `AudioQueue`，Linux 用 ALSA 设备名 `default`（交给 dmix 或 PipeWire-ALSA）。
- 播放在送入声卡的 PCM 缓冲上计算 RMS，直接驱动嘴形。
- 录音采集为 16 kHz 单声道 WAV，再交给 Whisper。
- macOS 的 `Info.plist` 由发布脚本写入 `NSMicrophoneUsageDescription`，由系统提示负责授权。
- 旧配置 `audio_backend=webview` 不再切换实现，三平台都走原生设备。

### TTS 输出格式

三平台都只解码 RIFF/WAVE（PCM 或 IEEE 浮点）：

- OpenAI 兼容 `/audio/speech` 请求显式发送 `response_format: "wav"`，避免默认 MP3。
- GPT-SoVITS `/tts` 的 POST 请求和 GET 降级都显式指定 `media_type=wav`、`streaming_mode=false`，请求完整 WAV。
- IndexTTS-2 的 Modelverse [接口契约](https://github.com/uclouddoc-team/modelverse/blob/master/api_doc/audio_api/ttts.md)固定返回 WAV、`Content-Type: audio/wav`；不添加该接口未声明支持的格式参数。
- Custom HTTP 的请求体仍为 `{text, voice, speed}`。须在**自定义 TTS 服务端**配置输出 PCM WAV，并返回正确的音频 Content-Type；仅把 MP3/OGG 的 Content-Type 改成 `audio/wav` 无效。

非 WAV 仅使当前播放失败，并给出以上配置提示，后续 WAV 播放不受影响。没有页面解码回退。

## 5. 数据和模型

正式运行数据只位于 `<PackageRoot>/data`，由不可变 `AppStoragePaths` 管理；不存在可写时明确失败，不回退系统目录。新布局包括 `core/database`、`core/security`、`knowledge/documents`、`resources/installed/live2d`、`plugins` 和 `diagnostics/logs`。运行时不会读取旧版应用数据目录。

Live2D 资源只在本地 `<PackageRoot>/data/resources/installed/live2d/` 管理。产品模型范围为 `arg-nori` 与 `nori`；没有模型 CDN、远程下载、网关、自动更新或随 release 下载模型的步骤。

敏感配置使用 `nsec2:` AES-256-GCM。旧 `enc:dpapi:` 只在 Windows 兼容；macOS/Linux 无法解密旧值时只要求重新输入对应密钥。

## 6. 构建与发布

开发/CI：

```bash
pnpm install
pnpm check:todo
pnpm build
pnpm test
dotnet build Nori.slnx --configuration Release
dotnet test Nori.slnx --configuration Release --no-build --no-restore
```

Windows 发布：

```cmd
publish.bat
```

它固定执行 `dotnet publish --self-contained false`，不提供 self-contained、安装器或系统级更新服务（应用通过 GitHub Release 槽式自动更新机制升级）。正式 ZIP 的目标机必须自行安装：

1. Windows x64；
2. .NET Runtime 10。

浏览器 DOM 自动化已拆分为独立插件 [Nori.Plugins.Browser](https://github.com/MF-Dust/Nori.Plugins.Browser)（`io.nori.browser`），主程序发布包不再包含 Playwright。插件 manifest 只声明 `windows` 平台，其他平台会标记为不兼容；目标机还必须安装 Microsoft Edge stable。插件只连接 `msedge` channel，使用临时隔离 profile，不会下载浏览器。

CI 通过 `scripts/package-windows.ps1` 检查可执行文件、`Live2DCubismCore.dll` 和 framework-dependent 内容，再生成 ZIP、SHA-256、CycloneDX SBOM、不猜测许可证的 `THIRD-PARTY-NOTICES` 与 `UPDATE-win-x64.json` 清单。`scripts/smoke-published.ps1` 会以临时 profile 启动 `first-run` 与 `initialized`，等待 JSON readiness 并强制有界退出。Linux CI 安装 `libgtk-3-0`；ALSA 在 Ubuntu 24.04 起安装 `libasound2t64`，更早的发行版安装 `libasound2`。

macOS/Linux 的 `publish.sh` 生成与 Windows 相同的完整 root；Release workflow 当前发布 `linux-x64` 与 `osx-arm64`，归档整个 root（包括 launcher sidecars、槽和隐藏的 `.current`），不把 data、.NET runtime 或 source map 带入包。`<PackageRoot>` 必须可写且整包可移动。

## 7. 已知前提

- Windows 透明窗口的实际验证已完成；macOS/Linux 的能力表和编译门不替代桌面环境实测。
- Linux X11 与 Wayland 行为不同，XWayland 只有在存在可用 `DISPLAY` 时才按 X11 能力处理。
- PurismCore v1.1.0 原生库覆盖 `win-x64`、`linux-x64`、`linux-arm64`、`osx-x64`、`osx-arm64`；macOS 使用 universal 库。显式 RID 和无 RID 本机构建均须匹配架构。Linux ARM64 现可交叉发布，但不因此加入当前 CI 实机验收矩阵。
- PurismCore 使用上游 MIT 许可；发布结构检查要求原生库同目录包含 `PurismCore.LICENSE.txt`，不再要求官方 Cubism Core 分发确认。来源与固定 SHA-256 见 `app/desktop/Live2D/README.md`；上层 SDK 和模型资源许可仍需独立确认。
