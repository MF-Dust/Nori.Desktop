# 跨平台支持与验收口径

Nori 共享 .NET 10 + Avalonia 12 原生宿主；播放和录音走各平台声卡。三平台均使用根 launcher、`.current` 与槽式 framework-dependent 包，Windows 仍是首要验收平台。

## 2. 能力驱动降级

平台能力来自 `IPlatformServices.Capabilities` 并进入 runtime snapshot，原生界面据此禁用或解释不可用功能：

- 原生 Wayland（没有 `DISPLAY`）用 `wl_surface.set_input_region` 做模型矩形穿透，区域是表面局部逻辑像素；嵌入的快捷聊天控件矩形始终可点，穿透开关打开时只去掉模型矩形。拿不到 Avalonia 表面或协议调用失败时停止同步并保持整窗可点。全局光标和窗口坐标仍然没有：视线只在窗口内跟随，不保存或恢复位置，Quick Chat 与桌宠共用同一窗口，拖动走 Avalonia 原生拖动。`SupportsTopmost` 保持 false；若合成器提供 `org_kde_plasma_window_management` 且版本至少 17，宿主另开短连接并只绑定版本 17，接住该版本的全部事件；`set_state` 入队后先刷新并完成一轮 roundtrip，再只把 pid 等于本进程且标题为 `Nori` 的窗口设为 KeepAbove。广告版本低于 17、没有 pid 或绑不上就保持不置顶。合成器重连后丢弃旧的模糊代理，不向已失效的 `wl_proxy` 发送请求。穿透同步若在已经设置输入区之后失败，会先把输入区恢复为整窗可点再停止。普通窗口在用户开启背景模糊且注册表里有 `org_kde_kwin_blur_manager` 时请求整窗模糊并使用玻璃底，否则保持深色实底，不改偏好。有 `DISPLAY` 时按 X11/XWayland 处理。X11 后端只有在 `AVALONIA_IM_MODULE`、`GTK_IM_MODULE`、`QT_IM_MODULE` 为 `fcitx` / `fcitx5` / `ibus`，或 `XMODIFIERS` 含 `@im=` 时才会连接输入法；KDE Wayland 默认不导出这些变量，中文输入法因此不会挂上。宿主在这些变量都未给出可识别选择、且会话总线已有 Fcitx（否则 IBus）时，只为本进程补上 `XMODIFIERS=@im=fcitx` 或 `@im=ibus`，不修改桌面环境，也不覆盖 `none` 或已经写明的选择。探测总线失败则保持原环境并继续启动。原生 Wayland 的宿主和启动画面统一禁用服务端装饰协商（Avalonia `ForceDrawnDecorations`），窗口外观仍由宿主管理，避免隐藏后重显时被合成器加回系统标题栏。
- Linux 托盘以 StatusNotifier 宿主为准：启动时查询一次，之后在同一条会话 D-Bus 连接上监听宿主变化（不轮询）。没有宿主时 `supportsTray=false`：关闭主窗口改为最小化，主窗显示退出按钮；宿主在运行中消失时，已隐藏的主窗口恢复为不抢焦点的最小化任务栏入口。监听失败按无托盘处理并稍后重试，不静默吞掉失败。
- X11 桌宠按全局光标坐标拖动，达到 4 DIP 阈值后移动窗口；按下后保持指针抓取，左键松开或抓取丢失时保存位置并清除拖动压感；多键操作时即使右键仍按着，左键松开也立即结束拖动，随后松右键不会触发左键点击动作。不在按下时就发起 `_NET_WM_MOVERESIZE`，避免窗口管理器接管后吞掉松键事件，影响点击与拖动收尾。
- X11 输入形状按物理像素设置，需要 SHAPE 1.1+，否则 `supportsHitThrough=false`；桌宠与 Quick Chat 的交互矩形均按四边向外取整，避免分数缩放下控件边缘少覆盖一个像素；非 Windows 的模型矩形输入形状更新失败时停止同步并保持整窗可点，不打断 OpenGL 渲染。
- 再次从应用菜单或命令行启动时，第二实例不打开数据库、不执行迁移，而是通知首实例恢复已最小化的主窗口并显示后退出。Linux/macOS 的单实例 Mutex 按当前用户生效、不区分 session，因此不同终端、登录自启与菜单启动也只会保留一个实例。唤起管道仅允许同用户连接，不接受命令或用户数据；socket 位于 `$XDG_RUNTIME_DIR`，缺失时退回用户临时目录并以用户名区分，不在共享 `/tmp` 中与其他用户争用同一路径。唤起通道无法建立或监听中断时保留单实例保护并记录告警，不阻断启动。安全模式不会激活已有实例，启动尚未完成时保留唤起请求。Wayland 下恢复窗口不代表可以绕过合成器的焦点策略。
- 运行时不具备能力时不会以异常作为常规控制流；调用前先读能力标志。

### Linux X11 输入形状验证

在支持 SHAPE 1.1 的 X11/XWayland 会话下，可显式运行原生输入区域回读测试：

```bash
NORI_TEST_X11=1 dotnet test Nori.Desktop.Tests/Nori.Desktop.Tests.csproj --configuration Release -m:1 --filter 'FullyQualifiedName~LinuxInputShapeTests'
```

上述开关只运行未映射窗口的形状回读测试，覆盖 Quick Chat 125% 缩放后的完整边界、整窗穿透与恢复接收输入；不移动真实鼠标、不显示窗口。原生 Wayland 不运行此测试，也不声明 X11 输入形状能力。

另有实际点击投递测试，会创建映射窗口并通过 XTEST 移动指针、按下和松开左键，验证模型矩形内接收、矩形外投递下层窗口、整窗穿透和恢复接收。**不要在用户桌面直接设置 `NORI_TEST_X11_POINTER=1`。** 已安装 KWin、XWayland、D-Bus 与 `libXtst` 时，可在 Release 测试构建和当前架构 `publish.sh` 发布后运行：

```bash
NORI_TEST_LINUX_DESKTOP=1 python3 scripts/linux-integration.test.py IsolatedDesktopTests
```

脚本创建独立 HOME、配置、runtime 和会话 D-Bus，使用 KWin virtual 帧缓冲与独立 XWayland，只有该隔离合成器允许 XTEST 注入。输入区域回读与点击投递均已通过；同一隔离桌面还通过了真实槽式发布包经根 launcher 启动的 X11/Wayland × first-run/initialized/initialized safe-mode 六种检查，结束或超时都会回收进程组，不修改用户桌面配置。

本机另以独立临时资源和缓存运行原生 `PetWindow`，`arg-nori`、`nori` 两份模型均完成原生 GL 画面及 alpha 命中区域生成、实际指针按下、60×40 物理像素拖动、位置落盘、透明角落向下层窗口投递点击。该结果不代替不同桌面、混合 DPI 和显示驱动上的视觉验收。

### 原生 Wayland 交互验证

隔离 KWin virtual 会话中，应用清空 `DISPLAY`、走 `UseWayland` 和 `SessionType.Wayland`；独立 XWayland 仅用于向隔离合成器注入输入，不是应用的窗口后端。已验证桌宠与内嵌 Quick Chat 的真实指针聚焦、键盘输入、隐藏/重显后草稿保留，以及由合成器执行的原生拖动；拖动后不落盘虚构的全局坐标。

本机复现过无边框桌宠重显后出现 28px 系统标题栏：客户端仍为 308×266，合成器窗口变为 308×294，后端装饰状态变为 `ServerSide`。禁止服务端装饰协商后，重显仍为 308×266 / `ClientSide`，且已在 720×480、1920×1080 两种虚拟输出下查看真实合成器截图；两种尺寸的聚焦、输入、草稿保留和原生拖动均通过。配置回归测试与共享启动画面的构建也通过。该结果只覆盖当时 KWin 会话的装饰、聚焦、输入、草稿和拖动，不宣称全局坐标已经可用，也不代替输入区、背景模糊和 KeepAbove 在其他合成器上的验收。

### 原生背景模糊

“个性化 → 界面 → 背景模糊”默认开启，自动保存至 `ui_background_blur_enabled`。关闭后立即恢复深色实底；系统不支持时也使用实底，但不修改用户偏好。普通应用窗口及自有独立对话框统一请求 `AcrylicBlur → Blur → Transparent`，仅实际获得 AcrylicBlur 或 Blur 时使用半透明窗口表面，普通透明不视为模糊成功。

Avalonia 12.1.1 的 Windows 路径由系统合成器提供 Acrylic；macOS 通过 NSVisualEffectView 的 BehindWindow 实现，深色外观由应用覆盖层保证；X11 路径仅在 KWin 开启合成时提供 Blur。Wayland 后端不回报模糊级别，宿主在合成器提供 `org_kde_kwin_blur_manager` 时自行请求整窗模糊，成功后才改用玻璃底。窗口背景与整窗根容器不得再叠加不透明底色遮住已启用的效果。系统设置、渲染后端和桌面环境均可能改变可用效果。

桌宠保持透明，Quick Chat 保留局部材质，不开启整窗背景模糊；这保证气泡之间及角色周围的透明留白。不能仅凭用户开关假定模糊已生效，要看当前窗口实际拿到的材质。

视觉验收必须使用真实桌面与窗口后方的高对比图案，对照开启、关闭和不可用状态；Headless 截图只能证明控件布局，不能证明系统已模糊桌面。macOS/Linux 未经对应桌面实测时应明确报告，不以编译通过代替验收。

### 手动窗口扫描

Quick Chat 输入框旁的扫描按钮进入选窗模式：悬停显示绿色轮廓，点击窗口后播放扫描线并把该窗口的截图发送给当前聊天 AI（需要模型支持图片）。也可用 Tab / Shift+Tab 切换、Enter 选定、Esc 取消；点击空白区域取消。扫描期间不把点击传给下方应用；隐藏桌宠或关闭 Quick Chat 会取消操作并丢弃迟到结果。

分析读数逐字显示，30 秒后隐藏；减少动态效果时立即显示全文并固定扫描线。芯片容量为 5 次，每 5 分钟恢复 1 次；余量与最近 32 条内容指纹/读数只保存在进程内，输入框重建不重置，退出应用后清除。同一截图的缓存读数不重复请求 AI 或消耗余量。截图不落盘、不进入聊天历史，仅选定后发送给已配置的 Provider；受保护或无法截图的窗口会报告失败。安全模式禁止扫描，非 Windows 平台点击时明确说明不可用。

扫描像素字体沿用 Nori.Web 的 Fusion Pixel 12px Proportional SC（2026.07.01），仅从 WOFF2 转为 TTF 容器；版权与 SIL OFL 1.1 随包位于 `licenses/fonts/FusionPixel.OFL.txt`。

## 3. 安全模式与诊断

`--safe-mode` 是三平台相同的人工启动开关，不依赖平台崩溃恢复机制。它保留原生窗口、日志、诊断 ZIP 和本地手动配置修复；MCP 自动连接、Proactive/Reflection、记忆后台维护、AI 伴侣交互和 Live2D 自动模型加载会被跳过，Bridge 入口也拒绝交互式联网、Provider/MCP/语音外部操作。Wayland 的能力降级仍由 `supportsHitThrough` 等快照字段决定，不会因安全模式改变平台声明。

连接测试和诊断导出都在宿主后台线程执行。连接测试不保存配置或内容；诊断 ZIP 只带脱敏、有界日志和 Agent 阶段/用量指标，不包含数据库、用户内容、请求体、录音、资源、凭据或真实路径。

## 4. 语音实现

语音不再依赖 Windows-only NAudio，也不再经过页面播放：

- C# `VoiceService` 选择 OpenAI、Custom HTTP、GPT-SoVITS HTTP TTS 和 Whisper STT。
- Windows 用 WASAPI，macOS 用 AudioToolbox `AudioQueue`，Linux 用 ALSA 设备名 `default`（交给 dmix 或 PipeWire-ALSA）。Linux PCM 以非阻塞模式打开，读写在短超时等待中重试；播放收尾也分轮等待，停止或取消不必等待声卡播完缓冲；收尾期间挂起会尝试恢复，系统信号中断会在下一轮重试且不重置等待期限；总等待以首次报告的剩余时长加 1 秒为上限，不可恢复的收尾错误会明确报告。
- 播放在送入声卡的 PCM 缓冲上计算 RMS，直接驱动嘴形。
- 录音采集为 16 kHz 单声道 WAV，再交给 Whisper。
- macOS 的 `Info.plist` 由发布脚本写入 `NSMicrophoneUsageDescription`，由系统提示负责授权。
- 旧配置 `audio_backend=webview` 不再切换实现，三平台都走原生设备。

### Linux 默认声卡排查与原生验证

Linux 始终打开 ALSA `default`，不绕过系统默认设备去抢占 `hw:`。初始化失败会分别提示检查默认输出或连接、启用默认麦克风，并保留底层原因。PipeWire 环境可用以下命令检查：

```bash
wpctl status
wpctl inspect @DEFAULT_AUDIO_SOURCE@
pw-metadata -n default
pactl list sources
```

`pactl get-default-source` 返回配置名称不代表已有有效默认输入；还应确认 `wpctl inspect @DEFAULT_AUDIO_SOURCE@` 能解析到节点。本机原生输入测试在应用 ALSA 参数时返回 `No such file or directory`，系统 `arecord -D default` 同样失败，且 WirePlumber 无法解析默认输入；因此真实麦克风验收仍被系统输入配置阻塞，未修改默认设备或绕过 `default`。

如果录音节点存在但没有 `default.audio.source`，还需检查其输入端口的可用性；前麦克风、后麦克风、Line-in 全部为 `not available` 时，单独执行 `wpctl set-default <节点编号>` 不会让端口变为可用。应先连接麦克风，或在系统声音设置中启用正确的输入端口，再设置默认输入；节点编号会随会话变化。`SUSPENDED` 本身只是空闲状态，不等于设备故障。不要把输出设备的 monitor 当成真实麦克风。

原生接口测试默认跳过，显式开启后播放只写静音，输入只短暂读取内存缓冲、不保存录音：

```bash
NORI_TEST_ALSA=1 dotnet test Nori.Desktop.Tests/Nori.Desktop.Tests.csproj --configuration Release -m:1 --filter 'FullyQualifiedName~AlsaNativeDeviceTests'
```

仅验证输出时，将筛选器改为 `FullyQualifiedName~AlsaNativeDeviceTests.DefaultOutputWritesDrainsAndStops`。也可在独立测试进程中通过 `ALSA_CONFIG_PATH` 将 `default` 指向 ALSA `null` 插件，以验证原生接口链路；这不算真实声卡或麦克风验收，不应修改用户的全局 ALSA 配置来让测试通过。

PipeWire ALSA 插件的播放收尾回调可能忽略非阻塞标志，因此宿主通过剩余帧数推进收尾；短音频显式启动，欠载后按设备报告的下游延迟等待尾音，避免阻塞停止或截断最后一包。若插件报告的剩余帧停滞不降，到达上限后即结束收尾并释放设备，不会无限占住播放队列。

### TTS 输出格式

三平台都只解码 RIFF/WAVE（PCM 或 IEEE 浮点）：

- OpenAI 兼容 `/audio/speech` 请求显式发送 `response_format: "wav"`，避免默认 MP3。
- GPT-SoVITS `/tts` 的 POST 请求和 GET 降级都显式指定 `media_type=wav`、`streaming_mode=false`，请求完整 WAV。
- IndexTTS-2 的 Modelverse [接口契约](https://github.com/uclouddoc-team/modelverse/blob/master/api_doc/audio_api/ttts.md)固定返回 WAV、`Content-Type: audio/wav`；不添加该接口未声明支持的格式参数。
- Custom HTTP 的请求体仍为 `{text, voice, speed}`。须在**自定义 TTS 服务端**配置输出 PCM WAV，并返回正确的音频 Content-Type；仅把 MP3/OGG 的 Content-Type 改成 `audio/wav` 无效。

非 WAV 仅使当前播放失败，并给出以上配置提示，后续 WAV 播放不受影响。没有页面解码回退。

## 5. 数据和模型

正式运行数据只位于 `<PackageRoot>/data`，由不可变 `AppStoragePaths` 管理；不存在可写时明确失败，不回退系统目录。新布局包括 `core/database`、`core/security`、`knowledge/documents`、`resources/installed/live2d`、`plugins` 和 `diagnostics/logs`。运行时不会读取旧版应用数据目录。

Live2D 安装后的资源统一位于 `<PackageRoot>/data/resources/installed/live2d/`。产品模型范围为 `arg-nori` 与 `nori`；发布归档不包含模型，首次运行模型步骤、启动时缺失的所选模型以及模型设置页可从 `https://static.nori.mom` 获取内置模型。下载只读取 `model3.json` 引用的资源，使用有界、禁止重定向且经过路径校验的请求，在同卷暂存后复用资源导入校验。安全模式不下载，离线时可使用本地 ZIP 或文件夹导入；不提供远程模型自动更新、签名 URL 网关或暂停/恢复下载。

敏感配置使用 `nsec2:` AES-256-GCM。旧 `enc:dpapi:` 只在 Windows 兼容；macOS/Linux 无法解密旧值时只要求重新输入对应密钥。

### Linux 原生 GL 验证

真实 GLES 测试可在 Windows ANGLE 或 Linux 系统 EGL 上显式运行，默认 CI 不开启。Linux 需要可用的 EGL display 与 `libEGL.so.1`；测试直接创建两个不共享资源的上下文，不连接用户模型、麦克风或网络。没有模型资源时可先验证合成、阴影与命中掩码：

```bash
NORI_TEST_NATIVE_GL=1 dotnet test Nori.Desktop.Tests/Nori.Desktop.Tests.csproj --configuration Release -m:1 --filter 'FullyQualifiedName~OpenGLTextureQuadTests' --logger 'console;verbosity=detailed'
```

测试覆盖 GLES 2/3 请求下的像素回读与 GL 状态恢复，并输出实际渲染器名称；软件光栅器通过不等于硬件 GPU 验收。当前 Linux Mesa / Radeon RX 580 2048SP 环境已在 X11/XWayland 默认 display 与 `DISPLAY= EGL_PLATFORM=wayland` 两种入口通过上述六种原生渲染场景，ALSA `default` 也已通过短静音输出、收尾与停止测试；麦克风的环境阻塞及实际点击投递的独立验证见上文。

安装了 `arg-nori` 与 `nori` 测试模型后，再同时设置 `NORI_TEST_LIVE2D_ASSETS=1` 与 `NORI_LIVE2D_FIXTURES=<模型父目录>`，验证真实模型的 720×480、1080p 绘制与上下文隔离。模型提交测试属于 `BridgeCommandsTests` 分部类，筛选文件名 `NativeModelCommitTests` 不会执行这些测试，应使用方法名：

```bash
NORI_TEST_NATIVE_GL=1 NORI_TEST_LIVE2D_ASSETS=1 NORI_LIVE2D_FIXTURES=/path/to/live2d \
  dotnet test Nori.Desktop.Tests/Nori.Desktop.Tests.csproj --configuration Release -m:1 \
  --filter 'FullyQualifiedName~NativeGlHarnessTests|FullyQualifiedName~原生候选失败和过期准备不替换已提交模型|FullyQualifiedName~切换模型清除旧眨眼和指针来源|FullyQualifiedName~仅覆盖当前模型时请求热重载且安全模式不自动加载' \
  --logger 'console;verbosity=detailed'
```

当前 Linux 环境已用内置模型下载器在独立临时目录安装两份模型，真实模型门控回归 68 例全部通过；上述原生绘制、候选失败回滚、切换状态清理和导入热重载共 9 例，在 X11/XWayland 与 `DISPLAY= EGL_PLATFORM=wayland` 两种 EGL 入口均通过。直接 EGL 回读不替代 Avalonia 透明窗口合成及桌面交互验收。

本机复现过既有 Mesa 着色器缓存引发的 Radeon 驱动线程崩溃，空桌宠也会触发，禁用缓存或独立缓存后不复现。宿主现于图形初始化前把 `MESA_SHADER_CACHE_DIR` 固定到包内 `data/resources/cache`，仅更新 libc 环境供进程内 Mesa 的 `getenv` 读取，不修改 .NET 环境副本，因此启动的子进程保持用户原有的 `MESA_SHADER_CACHE_DIR` 值；重启后的新宿主会自行重新配置。修复后在原有用户环境下，两份模型的硬件渲染、实际点击、拖动和透明角落穿透均通过，不需要删除用户缓存或关闭硬件加速。Mesa 自行管理该目录下的驱动缓存子目录，不纳入诊断导出；若包内缓存以后损坏，仍可仅对本次启动使用 `MESA_SHADER_CACHE_DISABLE=true ./Nori` 诊断。该修复隔离缓存，不代表托管异常处理能够恢复所有原生驱动崩溃。

## 6. 构建与发布

开发/CI：

```bash
pnpm install
pnpm check:todo
pnpm build
pnpm test
dotnet build Nori.slnx --configuration Release
dotnet test Nori.slnx --configuration Release --no-build --no-restore
```

Windows 发布：

```cmd
publish.bat
```

它固定执行 `dotnet publish --self-contained false`，不提供 self-contained、安装器或系统级更新服务（应用通过 GitHub Release 槽式自动更新机制升级）。正式 ZIP 的目标机必须自行安装：

1. Windows x64；
2. .NET Runtime 10。

浏览器 DOM 自动化已拆分为独立插件 [Nori.Plugins.Browser](https://github.com/MF-Dust/Nori.Plugins.Browser)（`io.nori.browser`），主程序发布包不再包含 Playwright。插件 manifest 只声明 `windows` 平台，其他平台会标记为不兼容；目标机还必须安装 Microsoft Edge stable。插件只连接 `msedge` channel，使用临时隔离 profile，不会下载浏览器。

CI 通过 `scripts/package-windows.ps1` 检查可执行文件、`Live2DCubismCore.dll` 和 framework-dependent 内容，再生成 ZIP、SHA-256、CycloneDX SBOM、不猜测许可证的 `THIRD-PARTY-NOTICES` 与 `UPDATE-win-x64.json` 清单。`scripts/smoke-published.ps1` 会以临时 profile 启动 `first-run` 与 `initialized`，等待 JSON readiness 并强制有界退出。Linux CI 安装 `libgtk-3-0`；ALSA 在 Ubuntu 24.04 起安装 `libasound2t64`，更早的发行版安装 `libasound2`。Linux CI 还运行 `scripts/linux-integration.test.py`（桌面入口与冒烟脚本 fixture），并在 Xvfb + 独立 D-Bus 会话中以临时 profile 冒烟发布包的 first-run、initialized 与安全模式启动（`scripts/smoke-published.py`）；D-Bus 协议单元测试自带私有 `dbus-daemon`。

macOS/Linux 的 `publish.sh` 生成与 Windows 相同的完整 root；Release workflow 当前发布 `linux-x64` 与 `osx-arm64`，归档整个 root（包括 launcher sidecars、槽和隐藏的 `.current`），不把 data、.NET runtime 或 source map 带入包。`<PackageRoot>` 必须可写且整包可移动。Linux root 另带 `linux-desktop.sh`（按 XDG 目录为当前用户注册菜单与登录自启入口，声明 `StartupWMClass=Nori.Desktop`）与 `nori.png`，移动发布目录后需重新执行 `install`。

## 7. 已知前提

- Windows 透明窗口的实际验证已完成；macOS/Linux 的能力表和编译门不替代桌面环境实测。
- Linux X11 与 Wayland 行为不同，XWayland 只有在存在可用 `DISPLAY` 时才按 X11 能力处理。
- PurismCore v1.1.0 原生库覆盖 `win-x64`、`linux-x64`、`linux-arm64`、`osx-x64`、`osx-arm64`；macOS 使用 universal 库。显式 RID 和无 RID 本机构建均须匹配架构。Linux ARM64 现可交叉发布，但不因此加入当前 CI 实机验收矩阵。
- PurismCore 使用上游 MIT 许可；发布结构检查要求原生库同目录包含 `PurismCore.LICENSE.txt`，不再要求官方 Cubism Core 分发确认。来源与固定 SHA-256 见 `app/desktop/Live2D/README.md`；上层 SDK 和模型资源许可仍需独立确认。
